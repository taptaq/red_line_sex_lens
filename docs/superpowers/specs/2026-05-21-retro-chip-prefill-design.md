# 发布后复盘 Chips 选择化设计

## 目标

把当前“发布后复盘”里几项需要人工手填的字段，改成**预设 chips 多选 + 手动补充**的形式，降低填写门槛，让用户不需要每次从零组织措辞。

本次重点改造字段：

- `偏差原因`
- `被验证信号`
- `被推翻信号`
- `规则优化候选`

## 范围

第一版只做前端录入体验优化，不改整套复盘数据结构的核心语义。

也就是说：

- 仍然保存到现有字段
- 仍然兼容旧记录里的纯文本内容
- 不新增外部服务
- 不引入新的后台配置页

本次不做：

- 历史自动学习 chips
- 全局自定义词库管理
- 复杂拖拽排序

## 交互定位

这些字段现在的问题不是“没有地方填”，而是：

- 不知道该写什么
- 不想每次都手打
- 同一类结论反复写

所以第一版的目标不是增加智能判断，而是把常见复盘结论沉淀成**可点选的短语**，手动补充只作为例外路径。

## 交互方案

每个目标字段都改成两层：

1. `预设 chips 多选`
2. `补充说明输入框`

保存时把两部分合并回当前字段。

建议表现形式：

- 上方：字段标题
- 中间：可多选 chips
- 下方：`补充说明` 小输入框或 textarea

### 选择规则

- 点击 chip 选中 / 取消
- 支持多选
- 已选 chips 用更明显但仍然清爽的高亮态
- 未选时保持弱背景

### 保存规则

保存到现有字段时：

- 先写已选 chips
- 再拼接补充说明
- 统一使用稳定分隔符，避免格式混乱

推荐：

- chips 用 `、` 拼接
- 若有补充说明，则追加为新的一段

例如：

```text
标题偏弱、合集不匹配、标签不准

补充：标题虽然命中了情绪词，但封面与正文承接太弱。
```

## 预设内容

### 偏差原因

- 低表现
- 标题偏弱
- 开头不够抓人
- 正文过长
- 正文信息密度不稳
- 标签不准
- 合集不匹配
- 风险判断偏差
- 参考样本不够贴
- 发布时间影响

### 被验证信号

- 标题结构
- 开头切口
- 合集匹配
- 标签匹配
- 风格稳定
- 情绪共鸣
- 互动点明确
- 风险预判准确
- 参考样本有效

### 被推翻信号

- 标题判断失准
- 标签判断失准
- 合集判断失准
- 风险偏高估
- 风险偏低估
- 表现高估
- 表现低估
- 正文长度失准
- 互动预期失准

### 规则优化候选

- 同类标题结构可提权
- 同类合集可提权
- 情绪共鸣标签可提权
- 风险词权重需上调
- 风险词权重需下调
- 正文长度阈值需调整
- 标签映射需补充
- 参考样本权重需调整

## 数据兼容

旧记录里这些字段已经可能是纯文本。

所以第一版必须兼容：

- 打开旧记录时，若文本里正好包含某些预设短语，则自动映射成已选 chips
- 其余未命中的残余文本，落进“补充说明”

这样可以做到：

- 旧数据不丢
- 新 UI 可逐步接管
- 用户无需手动迁移

## UI 风格

延续当前 sample-library / calibration modal 的视觉语言：

- 暖白底
- 轻边框
- chip 圆角较大
- 已选态清晰，但不过度跳色
- 整体保持“编辑台”感觉，不做后台控制台味

建议：

- 未选 chip：浅米白底 + 细描边
- 已选 chip：更深一点的暖色底 + 轻描边
- hover 态轻微提亮

## 实现边界

推荐落点：

- `web/app.js`
  - 构建 chips markup
  - 处理选择状态
  - 在读写表单时完成 chips 与文本之间的双向转换

- `web/styles.css`
  - chips 样式

- `test/success-generation-ui.test.js`
  - 锁定 chips 渲染
  - 锁定已选态
  - 锁定保存/回填时的拼接规则

若需要单独整理配置，可加一个轻量常量区，但第一版不建议上升到独立管理模块。

## 非目标

本次不做：

- 历史数据自动统计生成 chips
- 用户级别自定义 chips 管理
- 后台可视化维护 chips 列表
- AI 自动帮你勾选 chips

## 测试

至少补这些回归：

- 旧文本能正确拆成“已选 chips + 补充说明”
- 用户切换 chips 后，保存内容能稳定拼回原字段
- 多选 chips 顺序稳定
- 未选任何 chip 时，仍可只保存补充说明
- 打开已有记录时，已选态正确恢复
