# 生成新内容临时参考素材设计

## 目标

在“生成新内容”工作台中，新增两类仅对本次生成生效的临时参考素材：

- 参考图片素材
- 参考文本素材

这些素材用于帮助模型理解这次想靠近的视觉气质、内容角度和表达结构，但不进入正式样本库、不写入共享记忆、不沉淀为长期资产。

本次重点满足以下边界：

- 图片支持一次上传多张，最多 5 张
- 文本支持一次上传多个纯文本文件，并在本次生成前自动合并
- 没有上传图片时，不触发多模态图片理解，只走普通文本参考
- 所有素材都只在当前一次 `/api/generate-note` 请求内使用

## 设计决策

### 1. 素材定位

这批素材的定位是“本次生成的临时参考”，不是正式知识资产。

因此它们不参与：

- 成功样本入库
- 风格画像更新
- 共享记忆写入
- 生命周期记录
- 参考样本池筛选

这样可以避免用户只是临时给几张风格图、几份参考文案，就污染整个长期生成链路。

### 2. 前端交互

在现有“生成新内容”表单中新增两个上传区块，放在一句话需求和高级偏好附近，作为“本次生成参考素材”。

#### 参考图片素材

- 使用 `multiple` 文件选择
- 接收常见图片格式：`.png`、`.jpg`、`.jpeg`、`.webp`
- 最多保留 5 张
- 展示已选文件列表、文件名、数量
- 支持逐个移除
- 若超出 5 张，前端直接拦截并提示

#### 参考文本素材

- 使用 `multiple` 文件选择
- 接收纯文本文件：`.txt`、`.md`、`.markdown`
- 展示已选文件列表、文件名、数量
- 支持逐个移除
- 在提交前给出“合并后文本预览摘要”或总字数提示，帮助用户判断是否传多了

交互原则：

- 不引入新弹窗
- 不引入独立素材管理页
- 只在当前表单中完成选择、移除和提交

### 3. 请求结构

前端在提交 `/api/generate-note` 时，把临时素材直接带进 JSON payload。

建议新增字段：

```json
{
  "referenceAssets": {
    "images": [
      {
        "name": "cover-style-1.png",
        "type": "image/png",
        "size": 12345,
        "dataUrl": "data:image/png;base64,..."
      }
    ],
    "textFiles": [
      {
        "name": "notes.md",
        "contentBase64": "..."
      }
    ]
  }
}
```

说明：

- 图片沿用现有前端 `FileReader -> dataUrl` 模式
- 文本沿用现有前端 `arrayBuffer -> base64` 模式
- 不改成 multipart，避免新开一条上传解析链路

### 4. 后端处理策略

后端收到临时素材后，统一先做一次“临时参考素材归一化”，再传给生成 prompt 组装层。

输出结构建议为：

```json
{
  "referenceAssets": {
    "imageSummaries": [],
    "mergedText": "",
    "textFileNames": [],
    "imageFileNames": []
  }
}
```

处理规则如下。

#### 图片素材

- 只有在 `images.length > 0` 时，才调用图片理解能力
- 逐张提取结构化摘要，例如：
  - 画面主体
  - 构图方式
  - 配色与氛围
  - 封面信息密度
  - 可借鉴点
- 单张失败时只跳过该张，不中断整次生成
- 最终只保留适合 prompt 的简洁摘要，不把整张图片二次落盘

#### 文本素材

- 对每个 `textFiles` 项做 base64 解码
- 按上传顺序合并
- 清理明显的空白噪声
- 保留文件名，便于 prompt 中说明来源
- 对最终合并文本做长度上限控制，避免挤爆生成上下文

#### 无图场景

如果本次没有上传任何图片：

- 不触发图片识别
- 不调用多模态能力
- 只把文本素材合并结果作为普通文本参考注入 prompt

这是本次明确确认的行为，不做“无图也走视觉模型兜底”的额外分支。

### 5. Prompt 注入方式

在 `buildGenerationMessages()` 中新增“临时参考素材”区块，并和现有参考样本、风格画像、共享记忆并列展示，但优先级低于系统长期参考。

推荐结构：

- 临时参考图片摘要
- 临时参考文本摘要 / 节选
- 使用边界说明

建议加入的约束语义：

- 可以借鉴这些临时素材的表达角度、节奏、视觉氛围或信息组织方式
- 不要直接照抄文本素材原文
- 不要把图片里可能出现的品牌、文案或具体句子机械复写到结果中
- 如果临时素材和当前风格画像冲突，优先保持账号整体风格与合规边界

这样能让临时素材有效，但不会压过系统已经沉淀下来的长期风格和参考样本。

### 6. 生成链路边界

这次不改造 `generateNoteCandidates()` 的核心返回结构，也不新增独立素材产物卡片。

临时素材只影响：

- 生成 prompt 上下文
- 候选稿内容倾向
- 封面图 prompt 的主题锚点提炼

临时素材不直接影响：

- 候选稿排序打分逻辑
- 风险评分公式
- 推荐稿选择算法

也就是说，它是“输入上下文增强”，不是“评分规则增强”。

### 7. 错误处理

前端：

- 图片超过 5 张时直接提示，不提交
- 不支持的文本格式不加入请求
- 读取单个文件失败时提示该文件失败，并允许其余文件继续保留

后端：

- 文本文件解码失败时跳过该文件并记录 warning
- 图片识别失败时跳过该图片并继续生成
- 如果所有临时素材都失效，仍按原有生成流程继续，不因为参考素材失败而整次报错

### 8. 测试范围

#### UI

- “生成新内容”表单新增图片上传入口
- “生成新内容”表单新增文本上传入口
- 支持多文件展示与移除
- 图片数量上限为 5

#### API

- `/api/generate-note` 接受 `referenceAssets.images`
- `/api/generate-note` 接受 `referenceAssets.textFiles`
- 无图时不调用图片理解分支
- 有图时才构建图片摘要

#### Prompt / Workbench

- `buildGenerationMessages()` 会输出临时参考素材区块
- 文本素材会以“仅参考、不照抄”的方式进入 prompt
- 图片摘要会进入 prompt
- 没有图片时 prompt 中不出现图片理解内容

## 成功标准

完成后，用户应该可以在“生成新内容”里：

1. 临时上传最多 5 张参考图
2. 临时上传多个纯文本参考文件
3. 不改动长期样本库的前提下完成一次更定向的生成
4. 在没有图片时，只依赖文本参考正常生成
